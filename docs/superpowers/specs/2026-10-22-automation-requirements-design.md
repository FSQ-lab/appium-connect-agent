## 已有事实与目标

当前 `4c20068e7972edf85a213dfd2a8e45bb56a38d93` 的 Automation SPEC 只确认 Session、操作和观测的模块归属，没有 Automation 产品包。Runtime 有本地静态诊断和已有本地 Appium 连接范围；连接不是设备 Session，也不选择设备或创建 WebDriver。

Automation 的价值是管理可复用的自动化行为、Session 和资源，提供定位、等待、操作、观测。Integrations 负责特定 Agent/协议的接入、参数映射与呈现。必要的明确组合操作仍归 Automation；任务规划和业务结论由上层决定，不按能力“高级程度”划分模块。

当前需求平台组合为 **macOS 宿主 / Android 真机或已启动模拟器 / UiAutomator2**。Android、iOS、macOS 自动化目标之间尽量复用代码和逻辑；macOS 自动化目标与 macOS 宿主是不同概念。跨平台复用是架构原则，不表示本批同时交付 iOS/macOS 目标。

## 已确认需求

### 界面方式与能力边界

- 首版从 Android 界面结构出发，以控件操作为主。含 WebView 的应用通过 Native 方式处理 Android 实际暴露的结构；不承诺取得全部网页元素，不引入 DOM、CSS 或 WebView context 切换。
- 截图和图像识别后续再讨论。首版不提供绝对像素坐标的公开操作输入；允许宽、高分别归一化为 `[0,1]` 的相对坐标，底层做必要转换。坐标基准、边界和精度待技术设计核对。
- 只向用户询问产品取舍；官方能力、默认值和约束先查 Appium 对应版本文档/源码，不把可由文档回答的事实反复变成问卷。官方支持只证明可复用，项目接入与验证后才能声明已支持。

### 定位、等待与普通动作

| 需求 | 已确认规则 |
| --- | --- |
| 属性定位 | 支持 resource-id、文本、content-desc 等属性及属性组合；可限定已定位父容器 |
| 包名 | resource-id 的 package ID 参数化，默认使用 Session 目标应用包名，单次可指定其他包名；无默认应用时的行为待设计 |
| 唯一性 | 操作目标及单控件查询须唯一，多个匹配报告歧义，不自动取第一个 |
| 匹配 | 文本默认精确匹配，不隐式去空白、忽略大小写或模糊匹配；其他方式通过 XPath 明确表达 |
| XPath | 保留直接输入入口，交 Appium 执行，不自行解析或改写；依据原始层级、类型和属性名，短字段不能直接替代原始 XPath 属性 |
| 控件引用 | 每次操作按定位条件重新定位；单次操作可使用官方元素对象，不建立跨次观测的自有 ref/缓存体系 |
| 条件等待 | 采用 wait-until 思路，5/15/60 秒三档，常规默认 15 秒，允许单次指定具体时长；满足条件立即继续 |
| 动作 | 条件满足后默认执行一次；收到有效 Appium/WebDriver 命令成功响应即完成，不自动等待页面变化或判断业务成功 |
| 超时与失效 | 条件等待不等于命令响应超时；响应丢失不能断言动作未执行，不自动重放；具体响应预算、取消与错误模型待设计 |

普通输入、清空、替换是三个操作：输入沿用官方行为，不额外隐式清空。等待不得通过反复点击/输入实现。不同操作的必要前置状态不能一律猜定为相同。

### 控件树观测的最终统一方案

1. 调用方直接请求当前界面的结构，或明确指定父容器读取其内部结构。完整仅指本次 Appium 实际提供的结构，不包含尚未加载的列表内容，也不承诺设备的全量真实界面。
2. 底层提供结构化 JSON，保留节点、原始父子关系、完整文字、定位属性、必要状态和几何信息。上层按业务需要转换为文本、摘要或协议内容。
3. 上限 **64 KiB = 65,536 UTF-8 字节**，按精简后 JSON 序列化大小计算；未超限返回请求范围完整结构，超限自动返回该范围的当前可见内容及必要祖先。
4. 自动缩小范围必须明确标记“仅可见区域，不代表完整结构”。可见区域仍超限时明确报告范围过大，由调用方指定更小父容器；不截文字、不静默丢尾部节点。
5. 部分可见控件保留完整文字/属性，并标记部分可见；可见不等于一定可操作。祖先的来源、可见性判定和多窗口坐标需技术核验。
6. 不自动滑动或遍历页面，不做分页、游标、历史快照续读或差异输出；每次结果独立可理解。上层决定下一次滑动与观测。
7. 默认设置 `enableMultiWindows=true`，保留不同窗口结构和来源，仍适用同一大小与范围规则。窗口来源的实际可获取性待核验。
8. 支持按需读取指定控件附近的原始结构/完整定位依据，仍受 64 KiB 返回上限约束，须说明覆盖范围，不能以局部结构推断全局唯一性；同时支持按定位条件查询唯一控件并选择返回属性，JSON 返回。

64 KiB 是用户确认的项目阈值，不是上游推荐或已证明的 token 上限。整份响应与树载荷的计量边界、JSON 编码参数、元数据开销、超大单节点、原始结构与 JSON 的对应仍待技术设计，不在本次整理中凭空确定。

“首版无损”的准确含义是：不有损删除所返回范围内的节点、层级和实际内容，省略规则明确、完整定位依据可获取；不是逐字还原原始 XML 的承诺。范围切换会缩小覆盖范围，必须如实说明。

### 单控件字段精简规则

| 对象 | 最终规则 |
| --- | --- |
| 重复文字 | 同一控件内属性原文完全一致才合并，保留属性对应关系；不合并不同控件，不清洗空白/换行/大小写 |
| 字段名 | 使用固定一一对应短名，示例 resource-id → id、content-desc → desc、类型 → type、文字 → text；正式 schema 尚未确认 |
| 维护位置 | Automation 代码中集中维护映射，实际序列化使用同一来源，Integrations 复用；未来 SPEC 记录含义 |
| 类型 | 标准类型的可还原命名空间可提取；自定义类型或同名冲突保留完整名 |
| resource-id | 集中声明默认包名，其他包显式保留，非标准格式原样；须能还原定位输入 |
| enabled | 已知 true 可省略，false 明示 disabled，未知明确标注 |
| focused | true 明示 focused，已知 false 可省略，未知明确标注 |
| checked / selected | 适用时明确真、假、未知；不适用不输出，不把未选中省略成未知 |
| 空属性 | 普通空描述可省略；输入框为空等有意义的空值保留；缺失、不适用与读取失败/未知区分；空格、0、false 不按空值丢弃 |
| 几何信息 | 首版保留；子父边界完全相同且父级数据可获取时，可表达同父级，不以相近/重叠代替相同 |

状态数组暂不采用。空容器折叠（Q16.1）没有获批，首版不折叠；默认 200 字符预览、几何信息默认省略已被最后统一确认替代。8/32 KiB、分页/游标都是被替换的候选。

### 设备、Session 与应用管理

| 需求 | 最终规则 |
| --- | --- |
| 设备发现 | Automation 提供已连接真机和已启动模拟器的标识、名称、连接状态；ADB 薄适配在 Automation 内部，库或调用方式待选型 |
| 选择策略 | 上层明确指定设备，不自动选第一台，不创建/启动模拟器，不建设任意 ADB 命令入口 |
| 生命周期 | 上层显式创建/关闭，Session 跨多次调用复用，Automation 管理实际资源 |
| 应用输入 | 支持已安装应用 package ID 和显式本地 APK；应用参数、安装准备复用官方能力 |
| 数据默认值 | 默认保留数据，不额外强制清空/卸载重装；显式给 APK 允许官方必要安装准备，不承诺“绝不安装” |
| 创建时启动 | 默认不启动，允许显式开启；沿官方 autoLaunch 名称/语义设计，不创设 keep/activate/restart 模式 |
| 重启与重置 | forceAppLaunch、app/appPackage/appActivity、noReset/fullReset 等按官方交互设计，不重写安装或应用状态机；冲突组合待核验 |
| 关闭默认值 | 已确认 noReset=true、shouldTerminateApp=false；允许通过官方参数明确要求终止，不能只看单个参数忽略组合 |
| 空闲 | 默认 newCommandTimeout=0，允许上层覆盖；与 5/15/60 秒条件等待、命令响应超时区分 |
| capabilities | 保留官方参数入口；未指定项使用项目默认值，明确设备/平台/UiAutomator2 或首版范围冲突时报错，不静默覆盖；确切白名单与优先级待设计 |
| 设备占用 | 同设备已有本库 Session 时拒绝后来者，创建前占用，确认关闭后释放，关闭结果未知不能直接判空闲；外部客户端抢用不在保证内 |
| 多设备 | 不添加全局单 Session 限制或并行调度器；不同设备可分别使用，具体并行资源沿官方能力配置；与 Runtime 接缝尚未解决，不能宣称现有实现支持并行 |
| 失效 | Session 失效/设备断开报告错误，由上层决定重建，不自动重建或重放 |

独立应用接口首版包含：启动/激活（activateApp）、终止（terminateApp）、状态查询（queryAppState）、安装（installApp）、卸载（removeApp）、清空数据（clearApp）。后三项按上层显式调用执行，不改变“默认保留数据”。本次文档任务没有授权执行任何设备、应用安装/卸载/清空动作。
