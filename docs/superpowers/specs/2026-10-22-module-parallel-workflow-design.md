## 已确认模式

1. 每模块独立 worktree 与 session，每个模块同时只实现一个 feature；跨模块仅在已授权、所需依赖已验收并进入主分支、共享文件不冲突时并行。
2. 首轮候选为 Runtime 与 Configuration。Runtime 沿已有 feature 拆分、顺序、验收推进；Configuration 先设计再授权实现。本流程落地不创建这两个产品任务，也不扩大原 Runtime 授权。
3. 下游只等待实际所需的已验收能力，不一律等待上游整个模块完成；模块整体验收和真实链路义务仍保留。产品平台扩展仍另行确认。
4. 串行模式由一个开发 session 兼任统筹，既有干净工作区可复用，不强制多个 worktree、消息或资源排期；独立审查仍需新上下文。
5. 支持 Codex 与 Copilot，一轮可只使用一种工具。原生通知仅在实际可用且具有人类消息授权时使用；没有原生通知时采用持久记录及人工启动/继续 session。无跨工具实时通信、自动唤醒或守护进程承诺。
6. 每模块维护一份任务台账，Runtime 继续使用原台账；独立 worktree 内的未提交记录不会自动传播。统筹读取登记的本地台账绝对路径，或读取已推送分支上的固定版本。通知带任务 ID、版本与文件定位，不以聊天摘要替代原文。

## Git 交付与集成

- 发现实际远程默认分支，不硬编码 main；本仓库为 master，不自动改名。开始新任务前 fetch，并核对本地/远程主分支关系。远程不可读则不能宣称最新；本地主分支有未推送的其他任务或分叉时先核验交付身份，不自动发布无关提交。
- 每个 feature 从核验后的最新主分支创建 `codex/<module>-<feature>` 分支。模块 worktree/session 可复用；固定任务起点 SHA，开发中不随意更新。必要同步采用 merge，不 rebase/amend/force-push；保留原起点并登记导入的上游提交。
- 必要验证通过后，先显式暂存任务白名单并提交到任务分支，再审查固定提交。修复每轮追加提交，最多两轮自动修复；初次 full、后续 repair-only 不变。
- 第一轮提交差异为任务起点到待审提交，后续为上轮待审提交到修复提交；始终检查工作区、未跟踪及忽略的交付文件，干净 diff HEAD 不能证明已提交内容通过审查。记录固定 SHA、完整差异、哈希、路径及验证身份。
- 每个 feature 通过独立审查后，由唯一统筹在最新主分支上生成集成候选、验证并以 merge commit 保留历史。模块不能自行合入主分支；同期主分支更新则重新验证候选。冲突修复交对应模块，追加提交与必要限定复审；不能沿用修复前验证。
- 默认推送：确认主分支无保护、无要求 PR 的规则且推送权限允许时，统筹合并并普通 push 主分支。禁止借管理员权限绕过保护；保护状态未知或推送拒绝时不当作无保护，不反复探测写入，保留并推送任务分支。
- 主分支受保护时，任务分支普通 push，由用户主动要求才创建 PR，用户决定并执行最终 merge；Agent 不自动创建/合并 PR。PR 模式仍须保留提交历史，若仓库禁止 merge commit，报告策略冲突，不自行 squash。
- 等待 PR、集成或推送失败期间，该模块不启动下一 feature；其他无依赖模块可继续。只有验收且已进入共享主分支的提交才能成为下游依赖，不能依赖另一个任务分支。
- 主分支所在工作区脏或被其他 session 占用时，不更新其 checkout、index 或已签出的分支引用；可在隔离候选分支验证，推送本任务分支并报告 integration-blocked，等主分支可安全更新后完成。
- 审查后新增台账/证据提交需记录和核对差异，不能声称旧审查覆盖新 HEAD；纯记录增量由独立限定核验覆盖，不以增加记录反复触发产品全量测试。

## 所有权、任务交接与资源

- 模块负责人拥有该任务内模块源码/测试/SPEC/台账；统筹指定共享文件（Contracts、根 SPEC、依赖/锁文件、CI、流程）的唯一修改者。涉及共享变更时先决策契约，不能两条分支各自修改后再猜测合并。
- 消息与模块台账包含：原始授权定位、session/工具、仓库/worktree/分支、base/review/fix SHA、SPEC/设计身份、文件负责人、依赖、验证、审查、阻塞和接收人。沿用完整任务包，不创建平行的一套产品待办。
- Codex 的现有跨聊天工具可以用作增强，但不从父子 Agent 数量推断独立 session 能力；Copilot 的实际入口按宿主核验。只有被明确指定为模块根 session 的独立上下文才可承担模块协调，叶子工程/研究/审查角色继续禁止嵌套委派。
- 工作目录各自独立，Git 对象/ref 和远程仍共享；各自 .venv 与测试临时目录，不从其他 worktree 导入私有源码。不把 worktree 当设备或账号锁隔离。
- 真实 Appium/设备资源由统筹统一串行安排，任务包登记资源和权限；普通测试使用临时目录及端口。串行模式无需额外排期系统。
